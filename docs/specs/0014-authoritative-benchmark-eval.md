# 0014 — 评估 overhaul:覆盖率门槛 + 停用套件硬删 + 权威题库替换

**Status:** accepted(2026-07-28,grill 共识 12 项决策 + 用户逐项确认)
**ADRs:** 待补两篇——「停用套件硬删(W2 数据只加不删的例外登记)」「权威题库替换自造题库(W7 框架内的题库来源决策)」
**Tickets:** 91(覆盖率门槛后端)/ 92(覆盖率门槛前端)/ 93(停用套件硬删 + ADR)/ 94(MMLU 管线首发 + ADR)/ 95(GSM8K)/ 96(中文套件)/ 97(IFEval)/ 98(CRUXEval)/ 99(切换与校准)

## 背景与问题

生产榜单暴露三连问题(用户 2026-07-28 反馈,截图证据):

1. **「缺考状元」:** glm-5.0 指令遵循维度 0/10 判分 → 该维度分数为 nil(W7「裁判失败不计 0 分」)→ `totalScore` 把 nil 维度从分子分母同时剔除 → 总分 100.0 排第一,压过全部判完的模型。缺维度零成本,比记 0 分更损害榜单可信度,正面撞上防作假核心价值。
2. **旧版套件占位:** /admin 题库 tab 列表被四个 pre-v3 旧套件(「旧版套件」tag + 已停用)占据,用户明确要求「已停用的就别要了」。
3. **自造题库缺乏权威性:** 用户不再信任自造题目,要求引入公开权威 benchmark;且当前批次 LLM 裁判大面积失败(截图遍布 `·3/10`、`·1/10` 水印),判分确定性本身成了可信度瓶颈。

## 决策总览(2026-07-28 grill 共识,逐项确认)

| 域 | 决策 |
|---|---|
| 排名门槛 | 模型**所有启用维度都有分**(每维度至少判上 1 题)才计算总分、参与排名;W7「裁判失败不计 0 分」条款不动 |
| 出局呈现 | 行保留:名次 `–`、总分 `–` + 弱化水印「判分不完整 N/M 维度」,排在完整模型之后;维度格子照常显示真实分数;/eval、/board、/report/:token 三处同口径 |
| 停用套件 | **硬删**:suites + cases + eval_runs + eval_results 连带删除,无孤儿;已接受后果——旧批次报告永久失去对应维度列、总分按剩余维度重算;范围仅停用套件,启用套件内单个停用 case 不动 |
| 权威题库形态 | 公开权威 benchmark,HubScope 自己的 harness 经 Hub 端点跑;自执行、原始记录、W7 不可变性全部保留 |
| 维度映射 | 指令遵循→IFEval;推理→GSM8K;知识→MMLU;中文→CMMLU/C-Eval;代码→CRUXEval 式输出预测;**全部规则判分,零 LLM 裁判** |
| 代码判分 | CRUXEval 式输出预测,答案离线预计算,运行时精确匹配;不上沙箱(W8 单二进制与执行安全边界不动) |
| 题量采样 | 每维度冻结 **100 题**分层子集,每题 1 次(sample count=1);改子集=退役旧 Suite+铸新版(W7 既有机制) |
| 数据交付 | 题库子集作数据文件 `go:embed` 进单二进制,generation 幂等 seed;五数据集 license 逐集核对为验收项 |
| 新旧交接 | 新套件上线即整体切换,v3 停用并按硬删规则删除;先测试线(192.168.1.101)跑一个完整批次抽查分数分布再上生产;涨跌断点机制承担「题目已变更」 |
| 接受 trade-off | 公开题库的 contamination 风险(分数系统性偏高)换权威性与免维护 |

## 用户故事

1. 作为状态板读者,我希望第一名一定是所有维度都真实判过分的模型,以便相信榜首不是「没考完的幸运儿」。
2. 作为状态板读者,我希望判分不完整的模型在榜单上被明确标注而不是消失,以便区分「没评」与「评了没判上」。
3. 作为管理台读者,我希望判分不完整模型的各维度真实分数仍然可见,以便判断它实际表现如何。
4. 作为分享报告接收者,我希望分享页与控制台榜单口径一致,以便不怀疑被选择性呈现。
5. 作为公开页(/board)读者,我希望公开榜单与登录榜单同一排名语义,以便公开数据与管理台互证。
6. 作为评估运营者,我希望题库列表只呈现当前生效的套件,以便不被历史遗物干扰配置。
7. 作为评估运营者,我希望删除停用套件是彻底的(不留孤儿数据),以便库内状态自洽。
8. 作为评估运营者,我希望评测题目来自学界公认基准,以便榜单结论对内有权威性、对外可解释。
9. 作为评估运营者,我希望判分是确定性的规则判分,以便不再出现裁判模型故障导致的大面积低覆盖。
10. 作为管理员,我希望代码能力评测不在生产机上执行模型生成的代码,以便不引入新的安全边界。
11. 作为管理员,我希望题库随单二进制交付、离线可用,以便内网部署不引入运行时外部依赖。
12. 作为评估运营者,我希望每维度题量足以让分数差超出噪声,以便榜单名次差异有统计意义。
13. 作为状态板读者,我希望换题库后新旧批次交界处明确标注「题目已变更」,以便不把口径变化误读为模型退步。
14. 作为运维,我希望切换前在测试线见过一个完整批次的分数分布,以便上线即符合预期。
15. 作为合规关注者,我希望随二进制分发的题库子集 license 逐集核对并署名,以便再分发合法。

## 实现决策

### A. 覆盖率门槛(计分口径)

- **资格判定:** 后端在报告聚合层计算——模型在某 suite 的 AVG(score) 非 nil 视为该维度「有分」;全部启用 suite 都有分 = 完整,否则不完整。判定发生在报告生成时(读取路径),不改动 eval_results 数据。
- **总分与名次:** 不完整模型 total 为 null、rank 为 null;排序 = 完整模型按总分降序在前,不完整模型在后(次级序沿用既有 model_id 字典序约定)。全部模型不完整时榜单照常渲染(全体 `–`),不空态。
- **涨跌:** 不完整模型涨跌列显 `–`(无总分即无 delta,既有「不显示箭头」口径自然覆盖)。
- **API 契约:** 报告行新增完整性字段(如 `complete: bool` + 不完整维度计数),由后端计算、前端只消费;公开端点(/api/public/eval/board)与分享端点(/api/shared-reports/{token})同形状同步。
- **前端呈现:** 名次列 `–` 占位(复用 live 模式既有形态)、总分列 `–` + 弱化水印「判分不完整 N/M 维度」;维度格子照常(分数 + 档色 + 覆盖率水印不变)。新呈现约定须经 plan agent 设计评审并登记 ui-guidelines。
- **半成品 live 模式:** 运行中批次的既有「名次 `–`、字典序、维度格子四态」模式不动;覆盖率门槛只对已 settle 批次生效。

### B. 停用套件硬删

- **机制:** 一次性数据清理,随 `store.Open` 迁移机制执行、幂等(可重复跑):删除 `enabled = 0` 的 suites,连带其 cases、相关 eval_runs、eval_results;顺序从叶到根(results → runs → cases → suites)。
- **后果(已接受):** 引用这些 suite 的历史批次报告在读取时失去对应维度列,总分按剩余维度重算——报告是读取时现算,此为决策内行为,不做兼容。
- **W2 例外登记:** 「schema 只加不删」管结构不管数据,但行级删除历史评估数据仍属承重语义变更,须以 ADR 登记本决策与理由。
- **前端:** /admin 题库 tab 不再出现已停用套件(数据已删,无需 UI 过滤);「旧版套件」筛选选项在无 legacy 套件后自然空置,顺手移除。
- **范围边界:** 仅停用套件;启用套件内单个停用 case 维持现状(题库日常编辑语义,另议)。

### C. 权威题库替换

- **五套件映射(沿用 ADR 0010 既有五个 capability 维度,维度词表不变):**

| 维度 | benchmark | 判分方式 |
|---|---|---|
| 指令遵循 instruction | IFEval | 程序化指令校验器(官方 verification 函数的确定性移植) |
| 推理 reasoning | GSM8K | 最终数值提取 + 精确匹配 |
| 知识 knowledge | MMLU | 选项字母提取 + 精确匹配 |
| 中文 language | CMMLU 或 C-Eval(制作期按数据质量二选一,spec 验收时定) | 选项字母提取 + 精确匹配 |
| 代码 coding | CRUXEval 式输出预测 | 输出精确匹配(标准答案离线预计算) |

- **子集:** 每维度 100 题冻结子集;MMLU/CMMLU 按学科分层比例抽取,GSM8K/CRUXEval 随机抽取,IFEval 按指令类型比例抽取;子集清单随 seed 数据固化,一经铸入不可变(改子集 = 退役 + 铸新,W7)。
- **采样:** sample_count = 1,题量替代重复采样(100 题 CI ±10pp 以内,优于现 12 题 ×N 次的 ±28pp)。
- **判分实现:** 全部走既有 `rule` verdict 分派接缝扩展新 RuleMode/校验器;ADR 0008 归一化 profile 按题型各配一份(选项提取、数值提取、输出匹配、IFEval 免归一化)。**零 LLM 裁判**——judge 配置与代码本期保留不动(无消费方但不拆),清理另立项。
- **Case schema:** IFEval 需要结构化校验参数(instruction 类型 + 参数),Case 表加一个 JSON 校验参数列(W2 纯新增列,符合只加不删);其余题型复用既有字段。
- **交付:** 题库子集为数据文件(JSONL 或同级格式)经 `go:embed` 进二进制,generation 幂等 seed(沿用 seedbank 机制);CRUXEval 标准答案由一次性离线工具脚本预计算(脚本不进交付物);附署名/来源文件;五数据集 license 逐集核对 = 验收项。
- **nadir 与档色校准:** 新题库分数分布不同,各 suite nadir(ADR 0009)与 ≥80/≥50 档色阈值按测试线批次实测分布重新校准,校准值随实现 PR 提交并记录依据。
- **交接:** 新套件上线即切换;v3 自造套件停用并被 B 的硬删迁移一并删除;切换批次涨跌列由既有断点机制显示「题目已变更」;先测试线完整批次抽查(五维度分布合理性:不应全员 0 或全员 100)再上生产。

## 测试决策

- **Go 侧唯一接缝 = W1 黑盒 HTTP**(httptest + stub Hub + 假时钟 + 真 SQLite 临时库),不 mock 内部模块、不断言内部状态:
  - 覆盖率门槛:构造「某模型一个维度全部未判分」的 eval_results,经报告/公开/分享三个端点断言 rank null、total null、排序位置、完整性字段;断言完整模型排名不受不完整模型影响。
  - 硬删迁移:预置含停用套件 + 关联 runs/results 的库,迁移后经管理 API 断言套件消失、历史报告不再含该维度、迁移幂等(重复 Open 无副作用)。
  - 权威题库:stub Hub 返回精心构造的模型输出跑完整 eval run,断言各题型判分正确(选项/数值/输出匹配的正反例,IFEval 各类指令校验器的命中与不命中);seed 幂等(重复 Open 不重复铸题,不覆盖管理员编辑)。
- **前端 = vitest 纯函数**:排序(完整在前、不完整在后、次级字典序)、水印文案、完整性呈现分支(先例:`scoreTier.test.ts`、`sortRows` 测试)。
- **好测试的标准:** 只测外部可观察行为(API 响应、渲染输出),不测实现细节;判分器经 eval run 端到端断言而非单测内部函数。

## 范围外

- 执行型代码评测(HumanEval/MBPP + 沙箱 sidecar)——如需代码生成评测,另立独立项目。
- LLM 裁判代码与配置的清理(新体系无消费方,但拆除另立项)。
- 启用套件内单个停用 case 的删除。
- /eval 批次切换器、/admin 批次运行历史、趋势弹窗——「历史」指旧套件而非批次历史,这些全部保留不动。
- 外部公开榜单数据引入(LMArena 等)与 contamination 缓解。
- 运行中批次(live 模式)的任何呈现变更。

## 附注

- 用户选材参考 `leobeeson/llm_benchmarks` 仅为 benchmark 目录清单(无数据无代码);数据从各原始来源(HuggingFace/GitHub)取。
- contamination trade-off 已经用户确认接受:公开题库分数系统性偏高,换权威性与免维护。
- 三件事共享一个底层叙事:**榜单可信度 = 覆盖完整 + 题目权威 + 判分确定**;覆盖率门槛堵住「缺考状元」,规则判分根治裁判失败,权威题库解决题目公信力。
