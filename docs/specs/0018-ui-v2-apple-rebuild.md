# Spec 0018:UI v2.0 完全重构(Apple 风)

> 经 /grill + /impeccable 三轮决策确认(2026-07-31),用户原话:「所有的设计全部按照我发的来,不要想着跟现有兼容,我们是完全重构」。v2.0 设计简报(Apple 风,见附件决策表)为唯一事实源。
> 本 spec 推翻三处既有承重语义/承诺:① PRODUCT.md 品牌承诺(teal 电波青 → #007AFF 蓝);② 四态中文词表(正常/降级/宕机/告警)→ 三态(稳定/性能下降/服务异常,告警档显示层并入服务异常);③ 「闪烁 = failing 独占」动效语义 → 禁闪烁、引入 v2.0 §15 动效体系。实施首批前须落 ADR 0015(承重墙四问见文末「Further Notes」)。
> **后端状态机与告警管线(W5)不动**:failing 档保留在域模型、Lark 告警与告警历史;三态是显示层映射,不是域模型变更。

## Problem Statement

从用户(产品负责人)视角:现行 UI 是 Element Plus 后台工具风(顶部导航 + 卡片矩阵),视觉上接近传统运维平台。v2.0 的目标是换一副面孔与骨架——像 Apple 管理一套复杂 AI 系统:打开后 5 秒回答四个问题(整体是否健康 / 哪些模型有风险 / 异常影响范围 / 下一步该处理什么),气质是冷静、专业、可信、极简、精准,参考坐标 Apple System Settings / Apple Health / Linear / Vercel / Stripe。最终产品气质:不是 Grafana,是「AI 基础设施操作系统」。

## Solution

以 v2.0 简报原文完全替换现行视觉世界与信息架构:

1. **全站 macOS 设置风侧边栏外壳**(220px,含公开状态板),取代顶部 AppHeader;底部显示当前账号与版本。
2. **状态概览页健康优先**:72px+ 健康指数大数字 + 日环比 + Apple Widget 风指标区(可用率/请求量/平均延迟/异常模型数),趋势图为辅。
3. **模型状态改高级列表**(模型名称优先,指标辅助),行内嵌 24h 微条保留时间形态;卡片森林退役。
4. **三态词表中文主显**:稳定 / 性能下降 / 服务异常,小圆点 + 状态词,禁大面积红色标签。
5. **模型详情走右侧详情面板**(非弹窗),从发现问题到定位原因一条路径。
6. **图表 Apple Health 化**:轻线条、少坐标、少网格、强调趋势;平滑曲线(单调插值,不发明极值)。
7. **故障记录独立成页**:事件时间线(时间/异常类型/影响模型/持续时间/处理状态),从管理台设置区迁出。
8. **Benchmark 页 = 模型能力评估中心**:现有能力 suite 矩阵榜单的 Apple 产品对比风重构。
9. **动效体系按 v2.0 §15**:数字补间(500–800ms)、状态点呼吸、图表入场绘制(800–1200ms)、页面 Fade+Slight Move、hover 上浮 2–4px、局部刷新;reduced-motion 全局门控。
10. **健康指数后端口径先行**:当前 24h 窗口探测加权可用率(与既有 `availability_24h` 同定义)+ 前一 24h 窗口同口径环比,后端聚合,W1 黑盒测试。

## User Stories

### 外壳与导航

1. 作为任何读者,我希望每页左侧都有 220px 侧边栏导航,以便在任何页面一键切换到其他功能区。
2. 作为任何读者,我希望侧边栏当前页面项有轻量高亮(无强背景块),以便知道自己在哪里。
3. 作为未登录读者,我希望侧边栏只显示我能用的项(状态概览、Benchmark),以便不被会被弹走的入口误导。
4. 作为登录用户,我希望侧边栏底部显示我的账号与角色,以便确认当前身份。
5. 作为任何读者,我希望侧边栏底部显示版本号,以便报告问题时能给出版本。
6. 作为状态板读者,我希望公开页内容区保持 32–48px 留白、不铺满屏幕,以便页面有呼吸感。
7. 作为管理台读者,我希望管理页保持作业密度(密度按读者分档),以便高效完成配置与排查。
8. 作为任何读者,我希望页面切换是 Fade + 10px 内轻位移(200–300ms),以便感受到连续而非跳转。
9. 作为外部接收者,我希望分享报告页(/report/:token)不出现侧边栏与任何登录入口,以便我只看到物料内容。

### 状态概览(首页)

10. 作为状态板读者,我希望首屏第一视觉锚点是健康指数大数字(72px+),以便 1 秒内回答「整体健不健康」。
11. 作为状态板读者,我希望大数字旁显示日环比(较昨日 ±X%),以便知道趋势方向。
12. 作为状态板读者,我希望健康指数旁有结论词(如「存在异常」),以便数字有判读。
13. 作为状态板读者,我希望指标区以 Apple Widget 风展示可用率/请求量/平均延迟/异常模型数(标题 + 核心数字 + 变化趋势 + 轻量趋势线),以便 5 秒内掌握全局。
14. 作为状态板读者,我希望数字变化走 500–800ms 平滑补间而非跳变,以便轮询刷新不刺眼。
15. 作为状态板读者,我希望趋势图轻量辅助、不抢大数字主视觉,以便层级清晰。
16. 作为状态板读者,我希望汇总结论旁仍标注统计范围(启用端点集合),以便大数字不被误读为局部样本。
17. 作为状态板读者,我希望无探测数据时健康指数显示中性「暂无数据」而非 100%,以便「无数据」永不读作「全部正常」。

### 模型列表

18. 作为状态板读者,我希望模型以高级列表呈现(模型名 / 供应商 / 状态 / 24h 可用率 / P95 延迟 / 趋势 / 操作入口),以便按名扫读。
19. 作为状态板读者,我希望每行行内嵌 24h 微条,以便不展开就能看「几点开始炸的」。
20. 作为状态板读者,我希望异常模型的行按严重度排在可视区域前列(或一眼可辨),以便先看到该处理的。
21. 作为状态板读者,我希望模型名称是行内第一层级、指标为辅助层级,以便扫读以名为主。
22. 作为状态板读者,我希望长模型名截断 + hover 全显,以便列表不撑破。
23. 作为状态板读者,我希望点击模型行打开右侧详情面板,以便就地定位原因。
24. 作为状态板读者,我希望仍可按厂商/能力/协议筛选与分组,以便大清单下保持可导航。
25. 作为投屏读者,我希望列表在 1440×900 下一屏可读完核心信息,以便挂大屏巡场。

### 状态呈现(三态)

26. 作为状态板读者,我希望状态统一为三态:稳定(绿点)/ 性能下降(黄点)/ 服务异常(红点),以便状态语言简单一致。
27. 作为状态板读者,我希望状态永远是「小圆点 + 状态词」,以便颜色与文字双编码。
28. 作为状态板读者,我希望异常是局部强调而非大面积红色背景,以便页面保持冷静。
29. 作为管理台读者,我希望管理台表格中的状态词表与公开侧一致(同一三态),以便全站一种状态语言。
30. 作为运维,我希望降级端点仍带成因信息(可用性/延迟),以便判断该不该立即处理。

### 详情面板

31. 作为状态板读者,我希望点击模型后右侧滑出详情面板(非居中弹窗),以便不离开列表上下文。
32. 作为状态板读者,我希望面板顶部是模型名 + 当前状态,以便确认对象。
33. 作为状态板读者,我希望面板核心指标区展示 Availability / Latency / Error Rate,以便量化当前状态。
34. 作为状态板读者,我希望面板有 24h 延迟趋势与错误趋势,以便看形态。
35. 作为状态板读者,我希望面板有事件记录(错误时间/原因/影响范围),以便定位原因。
36. 作为状态板读者,我希望面板可一键打开完整详情页(/endpoints/:id),以便需要时深钻。
37. 作为分享者,我希望 /endpoints/:id 深链页仍然可用(新视觉),以便书签与分享链接不失效。

### 图表

38. 作为任何读者,我希望图表轻线条、少坐标、少网格,以便注意力在趋势而非网格。
39. 作为状态板读者,我希望趋势曲线平滑(单调插值),以便形态易读;同时无数据处断线,以便「无证据」不被连线伪造。
40. 作为状态板读者,我希望图表 x 轴永远是时间轴,以便不均匀的探测间隔不被呈现为均匀。
41. 作为状态板读者,我希望实时趋势图入场时曲线从左向右绘制(800–1200ms),以便感受到系统在运行。
42. 作为任何读者,我希望 hover tooltip 显示保真值(不随量程截断),以便精确读数。

### 故障记录

43. 作为运维,我希望侧边栏有一级入口「故障记录」,以便不钻进设置区找告警历史。
44. 作为运维,我希望故障记录是事件时间线(时间/异常类型/影响模型/持续时间/处理状态),以便快速理解事故过程。
45. 作为运维,我希望时间线包含既有全部事件类别(故障/恢复/分数大跌/厂商组告警/聚合发送/静默摘要等),以便审计面不缩水。
46. 作为运维,我希望按模型/类型/时间范围筛选事件,以便缩小排查范围。

### Benchmark

47. 作为任何读者(含未登录),我希望 Benchmark 页展示各模型的能力维度对比(现有 suite 能力点),以便判断哪个模型适合什么场景。
48. 作为榜单读者,我希望页面气质像 Apple 产品对比页而非排行榜表格,以便对比可读。
49. 作为榜单读者,我希望分数档位着色、涨跌、判分不完整水印等既有防作假语义在新视觉下保留,以便分数仍可信。
50. 作为管理台读者,我希望 /eval(评估中心)保留运行中批次的进度网格/实时分数/判分动态,以便运营评估。

### 动效与反馈

51. 作为任何读者,我希望 hover 可点元素轻微上浮(2–4px)+ 阴影轻增强,以便感知可点性。
52. 作为状态板读者,我希望自动刷新(10s)只更新变化区域,以便页面不整体重载。
53. 作为状态变化目击者,我希望状态点颜色渐变过渡(可带轻微呼吸),以便变化被注意到但不惊悚。
54. 作为开启 reduced-motion 的用户,我希望全部动效归零,以便前庭敏感不受困扰。
55. 作为任何读者,我希望交互三态(加载/空/错误)齐备,以便任何数据区块不失联。

### 健康指数(后端口径)

56. 作为产品负责人,我希望健康指数 = 当前 24h 窗口探测加权可用率(与 availability_24h 同定义),以便口径单一事实源。
57. 作为产品负责人,我希望日环比 = 当前窗口值 − 前一 24h 窗口同口径值,以便趋势是算出来的不是编的。
58. 作为 API 消费者,我希望概览响应同时返回当前值、前一窗口值与差值,以便前端不做二次推导。
59. 作为测试者,我希望该口径在 W1 接缝(httptest + stub Hub + 假时钟 + 真 SQLite)黑盒可测,以便回归网不新增接缝。

### 边界与物料

60. 作为分享者,我希望 StatusCard / EvalCard 导出物料随新世界重建(蓝色品牌区、三态),以便对外物料与产品同一张脸。
61. 作为分享者,我希望导出物料恒亮主题,以便打印与转发可读。
62. 作为窄屏访问者,我希望 /report/:token 与分享弹窗的既有 768px 断点处置保留,以便手机可读。
63. 作为管理员,我希望任务中心入口归入系统设置区,以便侧边栏保持七项简洁。

- `/endpoints/:id` 深链页保留(新视觉、壳内渲染);`/report/:token` 与 `/login` 壳外渲染(无侧边栏)。
- 侧边栏底部:当前账号(用户名 + 角色)与版本号;v2.0 的「当前环境 Production」不臆造——单二进制单实例,无多环境概念,以版本号承担。
- AdminView 与 AppHeader、PublicFooter 随外壳建成退役;未登录导航过滤逻辑迁入侧边栏。

### 令牌体系重建(三层架构保留,值全换)

- tokens.css 原始刻度按 v2.0 锚点重建:页面底 `#F5F5F7`、主文字 `#1D1D1F`、次文字 `#86868B`、品牌 `#007AFF`、绿 `#34C759`、黄 `#FF9500`、红 `#FF3B30`;各色生成功能阶(文字/图形/浅底分工随新色重新实测对比度并登记)。
- 字阶按 v2.0 §14:页面标题 32 / 模块标题 20 / 正文 14–16 / 核心数字 72+(新增 hero 档);字重轻量;字栈 = 系统字栈(PingFang SC / SF Pro 在 Apple 设备自然解析),零外部字体文件纪律不变。
- 圆角/阴影/间距刻度按 Apple 语法重定(大留白、轻容器、局部状态强调);80/15/5 色彩比例原则入 DESIGN.md。
- semantics.css 保留双值结构(暗色键位预留,首批不填暗色值);ep-theme.css 重写映射(仅管理台 EP 复杂件消费)。
- 状态点色映射:稳定 = 绿、性能下降 = 黄、服务异常 = 红;不再存在第四色(告警橙随三态合并退役,显示层)。

### 健康指数口径(后端,先行票)

- 概览响应新增:`health_score_24h`(当前 24h 窗口探测加权可用率,与既有 `availability_24h` 同一定义——按小时对齐求和 total/failures,启用端点集合,禁用端点不计)、`health_score_prev_24h`(前一 24h 窗口,即 24–48h 前,同口径)、`health_score_delta`(差值,任一侧无数据为 null)。
- 前端只展示不推导;无数据(null)渲染中性「暂无数据」,永不显示 100%。
- 「请求量」指标 = 24h 探测总次数(同源聚合,一并下发)。

### 显示层状态映射(前端唯一映射点)

- healthy → 稳定(绿);degraded → 性能下降(黄,成因副标签保留:可用性/延迟);down → 服务异常(红);failing → 服务异常(红)。
- 映射集中于单个纯函数( role.ts/degradeCauses.ts 集中原则先例),vitest 覆盖四入三出全组合;组件内禁写状态词字面量。
- 告警历史事件词表(九 kind)不受本映射影响——故障记录页展示事件类别,非状态。

### 图表纪律(Apple Health 化 + 防作假保留)

- 平滑曲线 = 单调插值(不发明极值、不越过数据点);null 断线保留;x 轴恒时间轴;tooltip 保真值不截断;失败探测延迟永不进 y 量程。
- 少坐标少网格:轴线/网格减到最少,刻度精简;ECharts 保留(不引新库),色板 JS 镜像随新令牌重建(亮主题单份,暗色键位预留)。

### 动效体系(§15 落地纪律)

## Testing Decisions

- **好测试的标准不变**:只测外部行为,不断言内部状态;后端只走 HTTP API 层。
- **唯一测试接缝 = W1(不新增接缝)**:健康指数与日环比聚合走 httptest + stub Hub + 假时钟 + 真 SQLite;先验 = overview `availability_24h` 既有测试(internal/server 概览测试)。假时钟推进跨 24h 窗口构造前一窗口数据。
- **前端 vitest 纯函数层**:四→三状态映射、健康指数/日环比格式化与 null 措辞、侧边栏按登录态过滤、列表行派生(严重度排序/微条聚合)、平滑插值不越界、数字补间 reduced-motion 分支;先验 = healthConclusion / overviewDots / format / latencySparkline 测试模式。
- **告警管线零改动证明**:internal/server 全部既有告警生命周期测试(Lark lifecycle / 聚合窗口 / 分组告警 / 静默时段)保持绿,作为「W5 后端不动」的回归证据。
- **视觉验收**:每批走 impeccable critique/audit(桌面 + 分享面窄屏),detector hook 规则随新 DESIGN.md 重建后恢复执法;混合期 detector 豁免登记。
- 不引入 e2e / 截图回归框架(本仓无此传统,不新增接缝)。

## Out of Scope

- **调用分析页**:无数据面(无请求级调用日志),简报第三受众需求需独立 spec 立数据面后再议。
- **后端状态机 / 告警管线 / 评估域逻辑**:failing 档、防抖、聚合窗口、分组告警、静默时段、Case 不可变、绝对分制全部不动。
- **暗色主题**:v2.0 未定义;令牌层预留双值能力,后续独立 spec。
- **移动端专门适配**:桌面优先不变;既有 768px 断点仅服务分享物料与 /report/:token,不扩大。
- **Element Plus 替换**:EP 保留管理台复杂件。
- **营销页 / 落地页 / 多环境概念**。
- **Benchmark 页臆造新维度**:「成本效率」等无后端评分口径的维度不入首版;榜单维度 = 现有 suite 能力点。
