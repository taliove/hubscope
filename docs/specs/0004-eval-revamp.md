# 0004 — 评估体系改造(判分口径 / 题库 v3 / Nadir 定标 / 进度网格)

**Status:** accepted(2026-07-22,经 grill-with-docs 共识)
**ADRs:** 0008(判分归一化 + 口径版本化)、0009(nadir 归一化定标,修正 0005 刻度)、0010(题库 v3 能力点重构 + 轮换)
**Tickets:** 49 / 50 / 51 / 52

## 背景

旧评估体系四个痛点:① exact 判分只 trim 空白,带引号/全角作答被误判 0;② 题库 toy 化、单 Suite 仅 12 题,单题权重 8.3%,统计不稳;③ 分数原始均分直出,高位挤压、区分度差,缺"跑分"式规范刻度;④ 批次进度只有一条百分比条,无视觉引导、不可随时查看,且运行中完全看不到分数。

## 决策总览

| 域 | 决策 | ADR |
|---|---|---|
| 判分 | 归一化管道(去成对引号、NFKC 全半角、折叠空白;大小写敏感)+ Verdict Profile 口径版本化,断裂复用 0007 断点 | 0008 |
| 题库 | 按能力点重构(30–50 题/能力点),新题型:结构化抽取/多步推理/代码理解/长文本摘要;**不做多轮、工具调用**;季度轮换 ~30%;judge ≤40%,judge sampleCount=3 | 0010 |
| 分数 | nadir 归一化定标(常数随版本锁定,审题人工标定);维度分同屏;Coverage + 采样数置信标记;不做参考锚点/百分位 | 0009 |
| 进度 | 模型 × 能力点 Progress Grid 为默认视图;半成品榜单可下钻查看但不排名次、带 Coverage 水印、未跑能力点不计入总分;AppHeader 全局进度入口 | 本 spec |

## 判分归一化(ticket 49)

- `verdict.go` 引入归一化管道,exact/contains 比对前先归一:trim、去成对引号(`"…"` `'…'` `「…」` `『…』`)、Unicode NFKC、折叠内部空白;**大小写保持敏感**。regex 模式不归一(模式本身即口径)。
- 管道版本化为 Verdict Profile(常量,如 `v1` = 仅 trim,`v2` = 完整管道);评估结果记录所用口径版本。
- 报告/趋势层:同模型结果序列中口径版本变化处形成断点,处理与 suite_version 断点完全一致(照画、标注「判分口径已变更」、不显涨跌箭头、大跌告警跳过)。
- 存量数据视为 `v1`,不回刷。

## 题库 v3(ticket 50)

- Suite 按能力点重构;能力点清单与权重在开票时定稿(候选:指令遵循/推理/代码/语言理解与生成/知识问答)。**「中文」作为语言维度取消**,中文题按能力点归位。
- 每能力点 30–50 题,难度仍分 basic/intermediate/hard;每题声明能力点、verdict 方式、nadir 标定依据。
- 新题型全部落在现有 rule/judge 双判分器上,不改造评估执行模型;多轮对话、工具调用**明确排除**(未来另立 spec)。
- seed 走新 generation(gen 3),旧题停用不删除(ADR 0007);轮换机制:每季度退役 + 铸新约 30%,轮换即版本递增。
- 管理台题库 tab 增加按能力点浏览与审题流转(生成候选 → 人工审 → 入库)。

## Nadir 定标与分数呈现(ticket 51)

- Case 或能力点级存 nadir 常数(随 Suite Version 锁定);能力点分 =(case 均分 − nadir)/(1 − nadir)× 100,clamp [0,100];总分 = 各能力点分加权平均(权重按能力点配,沿用 `suite_weights` 机制)。
- 榜单维度分同屏(总分 + 各能力点列),不再只靠 Suite 切换查看。
- 每个分数带置信标记:判分覆盖率(X/Y 题)+ 采样数;覆盖率不满的分数视觉上与满分覆盖区分。
- 未判分能力点不计入总分(分子分母同剔除,沿用现有口径)。

## 进度网格与实时榜单(ticket 52)

- **Progress Grid**:模型 × 能力点状态矩阵(等待中/运行中/已完成/失败),为运行中批次的**默认视图**;状态色复用 §3 语义色,批次级进度汇总在网格上方。
- **半成品榜单**:网格提供「查看实时分数」入口切换到榜单——运行中**不排名次**(按模型名字典序)、分数带「X/Y 题」Coverage 水印、未跑能力点显示「进行中」占位且不计入总分;批次 settle 后名次徽章出现 + ElMessage 提示。
- **全局入口**:AppHeader 在有运行中批次时显示轻量进度(「批次运行中 X/Y」),点击跳转 /eval。
- 后端:报告 API 透出 run 级明细(模型 × 能力点状态与覆盖率),现为聚合计数,需加字段,不动评估语义。
- 本票为 UI 重交互,开工前必过 design-owner 评审;落地后回写 ui-guidelines.md(Progress Grid、置信标记登记)。

> **分享视图边界(ticket 54 评审决议,修订 HIGH-1 口径):** 未完成批次的分享面(/report/{token})只公开进度元数据——模型 × 能力点四态 + 判分覆盖计数(X/Y 题),专用构造器 sharedProgressRows 从输入端结构性剥离 scores/weights/nadirs;**分数与名次(含 samples 置信标记)settle 前不出公开面**,「实时分数」为登录态专属。批次 settle 后分享面照常渲染完整榜单,与登录视图一致。依据:状态/覆盖率是运行元数据而非评估结论,不构成半成分数外流;模型名单 settle 后本就公开。

## 对 spec 0002 的修订

spec 0002 评审硬条件③「等待中/运行中批次榜单区呈进度态,不显示半成品名次」修订为:**运行中默认 Progress Grid,半成品榜单可查看但不排名次、带 Coverage 水印**;settle 前出现名次徽章仍禁止。

## Testing Decisions

沿用唯一接缝(HTTP API 黑盒 + stub Hub + 假时钟 + 真 SQLite)。各票核心断言:

- **49**:带引号/全角/多空白作答在 exact 下判对;大小写差异仍判错;结果记录口径版本;口径断裂处趋势含断点信息、不比涨跌;存量结果按 v1 渲染。
- **50**:gen 3 seed 幂等入库(旧题停用不删、不覆盖管理员编辑);能力点维度聚合正确;judge 题采样 3 次取均值;轮换(停用+铸新)使版本递增且历史 Run 渲染旧题。
- **51**:nadir 归一公式与 clamp;维度分 API 同屏返回;总分剔除未判分能力点;覆盖率字段正确。
- **52**:进度 API 返回模型 × 能力点明细;运行中报告不含名次信息;未跑能力点不计入总分;settle 后榜单完整。
