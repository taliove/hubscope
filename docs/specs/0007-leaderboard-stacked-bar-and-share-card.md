# 0007 — 评估榜单堆叠条改造与榜单分享卡片

**Status:** accepted(2026-07-27,grill 共识 + 用户评审通过)
**ADRs:** 无新增(不改评估语义;防作假边界沿用 ADR 0006/0007 与 spec 0004 既有口径)
**Tickets:** 75(堆叠条榜单行)/ 76(榜单分享卡片)

## 背景

两个痛点,均来自用户实机反馈:

1. **榜单行太丑、行高虚高。** 现行 Leaderboard 行是两层结构——上层「总分长条(长度=总分)」+ 下层「5 个能力点 mini bar strip(名字+小条+分数+覆盖率水印)」。15 个模型一屏放不下,mini bar 重复 5 次「名字+条+数字」视觉噪,且总分条与维度条是两个视觉系统,读者要自行拼接。
2. **评估域没有图片分享物料。** 状态板已有 StatusCard 卡片分享(批 56/59,PNG + 复制/下载 + 恒亮主题),评估域只有链接分享(/report/{token},ADR 0006)与打印 PDF。榜单是最具传播价值的评估产物(「我们评测了 N 个模型,这是排名」),缺一张可直接贴群里的图。

## 决策总览(2026-07-27 grill 共识,逐项确认)

| 域 | 决策 |
|---|---|
| 榜单行形态 | 单条**紧凑堆叠条**取代两层结构:维度段固定顺序从左连续堆叠,段宽 ∝ 该维度得分,未得分段不占宽度,右端统一留空 |
| 段宽口径 | 段宽 = 维度分 × 归一化权重,条总长与右侧总分数字**构造性相等**(防作假自洽,不产生第二口径) |
| 段内数值 | 宽度足够段内居中显示分数,窄段省略;每段 hover tooltip 恒有「能力点 · 分数 · 判分 X/Y 题 · 采样 N 次」 |
| 覆盖率水印 | 不满覆盖的段内分数后随「·8/10」压缩水印(宽度够时),窄段进 tooltip;「水印必须可见」修订为宽度自适应可见 |
| live 模式 | 已判分段照常堆叠 + 条右端灰字「N 个维度进行中 / N 个失败」,不占条宽、不进总分 |
| 维度切换 | 切能力点 = 行按该维度重排 + 该段不透明、其余段 ~40% 透明 + 右侧数字换该维度分;涨跌列仅总分视图 |
| 分享边界 | **仅 settle(done/failed)批次可分享**;运行中/等待中批次无入口(半成品分数不外流,spec 0004 同口径) |
| 卡片范围 | 卡片 = 当前所见(批次 + family 筛选 + 排序 + 维度视图高亮),范围行 chips 逐项标注;行封顶 20,超出收尾注明 |
| 入口 | Leaderboard 工具条右端 text 按钮(Share 图标),/eval、控制台报告页、公开分享页三处生效;控制台文案「分享图片」,公开页「保存图片」 |
| 导出机制 | 复用 StatusCard 全套基建(离屏双份捕获 + snapdom 2x + 复制/下载 + 复制降级 + 恒亮主题) |

## 堆叠条榜单行(ticket 75)

### 行构成

每行单层:`名次 + 模型名 + family tag + 堆叠条 + 分数 + 涨跌箭头`,行下 mini bar strip 整体移除。行点击下钻 ModelTrendDialog、键盘可达、hover 反馈、空态/失败态文案全部不变。

### 堆叠条语义

- 段顺序 = `report.suites` 固定顺序(与工具条能力点顺序一致),跨行可竖向对比同一维度。
- **段宽 = `score_i × (weight_i / Σw_scored)`**——归一化分母是「已判分维度」的权重和,与后端 `totalScore`(internal/server/report_scoring.go,未判分维度同时退出分子与分母)同口径,以总分刻度归一(满分条 = 100 分 = 满宽)。总分是加权平均(spec 0004),段宽不按已判分权重归一则条长与右侧总分数字成为两个口径,违反 grill 共识「不产生第二口径」。weights 来自 `report.weights`,前端归一化,不改 API。
- 未得分段(suite_scores 为 null,含未判分/未跑)不占宽度,已得分段从左边连续堆叠,右端统一留空;**空隙 = 丢分 + 未跑**,与总分数字同向。
- 段色按分数档位映射(≥80 success / ≥50 warning / <50 danger,与得分徽标同一映射,阈值口径不动);段间 1–2px 分隔(卡片底色),圆角仅条的两端(`--hs-radius-sm`)。
- 轨道底色 `--hs-brand-soft`,条高沿用现 20px。

### 段内数值与置信标记

- 段宽足够(实现阈值约 ≥44px,落地时定稿并回写 ui-guidelines)时段内居中显示 `formatScore` 分数(白字压色段,`--hs-text-xs`,600);窄段不显示。
- 每段 hover tooltip 恒有:`{能力点名} · {分数} · 判分 {judged}/{expected} 题 · 采样 {samples} 次`(沿用 ticket 51 confidence 口径);未判分段无段可 hover,信息由 live 标注承担。
- **覆盖率水印**:done 且 `judged < expected` 的段,段内分数后随「·8/10」压缩水印(宽度够时);宽度不够不追加,细节进 tooltip。ui-guidelines ticket 51/52「覆盖率水印必须可见」条款**修订为「宽度自适应可见,tooltip 恒兜底」**,设计评审登记。

### live 模式(运行中/等待中批次)

- 已判分维度段照常堆叠(口径同上);未跑维度不占宽。
- 条右端(总分数字前)灰字标注:`N 个维度进行中`(`--hs-text-xs` + `--hs-text-placeholder`);有失败 run 追加 `· N 个失败`(danger 色)。标注不占条宽、不进总分。
- 其余 live 约束不变:名次 `–` 占位、模型名字典序、排序/维度切换禁用、涨跌列隐藏、「进度网格 / 实时分数」切换不变。

### 维度切换联动

- 切到某能力点:行按该维度分重排(现有服务端排序语义不变),该维度段保持不透明、其余段降至 ~40% 透明,右侧分数数字换为该维度分;涨跌列仍仅总分视图出现。
- 「总分」视图 = 全段不透明 + 总分数字 + 涨跌列。
- family 筛选、排序下拉、baseline note 不变。

## 榜单分享卡片(ticket 76)

### 物料与弹窗

- 新组件 `EvalCard.vue`(榜单分享卡唯一渲染模板)+ `EvalShareDialog.vue`(预览 + 操作),结构、机制全面对齐 StatusCard/StatusShareDialog:720px 逻辑宽、2x 导出、离屏双份捕获(snapdom 对祖先 overflow 裁剪的规避)、复制图片(非安全上下文置灰 + 降级提示)/ 下载 PNG、**恒亮主题渲染**(暗色会话下捕获前临时脱离 `html.dark` 级联)。
- `utils/statusCardImage.ts` 泛化为通用卡片捕获(改名 `cardImage.ts` 或保留并复用,开票时定);文件名 `hubscope-eval[-scope]-YYYYMMDD-HHmm.png`。
- EvalCard 注册进 ui-guidelines §5(物料条目,对齐 StatusCard 登记粒度)。

### 卡片构成(自上而下)

1. **品牌区:** `--hs-brand` 4px 品牌条 + `--hs-brand-soft` 浅底 + BrandMark + Wordmark + 「评估榜单」标题(`--hs-text-2xl`/600)。
2. **范围行 chips(防作假,批 56 同构):** `批次 #N · 定时/手动 · 已完成/失败` 恒列;有 family 筛选 → `系列 · {family}`;非总分视图 → `维度 · {能力点名}`;非默认排序 → `排序 · {能力点名}`;涨跌基准 → `涨跌较批次 #M` 或不可比原因(`题目已变更,分数不可比` / `判分口径已变更,分数不可比` / `考核口径不同,分数不可比`)。实现口径经 ticket 76 设计评审登记为「较批次 #M」(chip label 已是「涨跌基准」,去重前缀)。chips 与卡片全部数字同源(同一份 report 响应),禁止引用页面其他聚合。
3. **failed 警示行(仅 failed 批次):**「N 个评估运行失败,仅统计已完成的评估集」,warning 语义,与页面 alert 同口径。
4. **榜单行:** 名次 + 模型名(截断)+ 堆叠条(含维度视图高亮态)+ 分数 + 涨跌箭头(仅总分视图且基准可比;不可比/持平/无基准一律不显示,不占位列)。**封顶 20 行**,超出收尾「另有 N 个模型未列出,详见评估榜单」。
5. **页脚:** hairline 分隔,左「生成于 YYYY-MM-DD HH:mm」,右 `location.origin`。

静态物料无 hover:段内数字与水印按页面同规则渲染(宽度够则显示),tooltip 信息不进卡片;堆叠条是静态图形,无动画语义冲突。空筛选结果:chips 保留 + 中性「暂无匹配模型」,禁止呈现为「全部正常」类结论。

### 入口与文案

- 按钮放 Leaderboard 工具条右端(text 型,Share 图标 + 文字,与批 59 分组分享入口同构),**仅 settle(done/failed)批次渲染**;三处生效:`/eval`、控制台报告页 `/campaigns/:id/report`、公开分享页 `/report/:token`。
- 文案消歧:控制台两页 = 「分享图片」;公开分享页 = 「保存图片」(读者是接收方);报告页 header 既有「分享」(铸链接,ADR 0006)改名「**复制链接**」,与图片分享消歧。
- 运行中批次三处均无入口:运行中进度信息分享由既有 /report/{token} 链接承担,不做图片(spec 0004 分享视图边界不变)。

## 对既有规范的修订

- ui-guidelines §5「Leaderboard 维度分同屏条带与置信标记」(ticket 51)与「Leaderboard 运行中半成品模式」(ticket 52)两条改写为堆叠条形态;覆盖率水印条款按上文修订;新增 EvalCard 物料与「分享图片/保存图片」入口登记;报告页「复制链接」改名登记。
- 不改后端:`rows / suite_scores / cells / weights / baseline` 数据齐备,本 spec 是纯前端改造,W1–W8 无触碰(评估不可变性 W7、分享边界 ADR 0006 均为沿用而非修改)。

## Testing Decisions

纯前端票,不新增 W1 接缝(HTTP 黑盒)测试;核心逻辑抽纯函数走 vitest(参照 `utils/statusCardSummary.test.ts` 先例):

- **75**:`stackSegments(row, suites, weights)` 纯函数单测——段宽加权归一、未得分段零宽、权重和边界(全 null / 单 suite / Σweights=0 防御)、档位色映射、live 标注计数(进行中/失败)、水印压缩判定。维度切换高亮与右侧数字切换走组件级手测清单。
- **76**:`buildEvalCardSnapshot(report, query, viewSuite)` 纯函数单测——范围 chips 生成(无筛选/逐项/不可比基准三分支)、failed 警示、封顶 20 与收尾计数、空筛选中性态。手测清单:三处入口可见性(settle/运行中)、暗色会话导出亮主题 PNG、HTTP 裸 IP 复制降级提示、长模型名截断。
