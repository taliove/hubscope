# 0009 — 评估榜单矩阵化重构

**Status:** accepted(2026-07-27,grill 共识 + 用户评审通过)
**ADRs:** 无新增(不改评估语义与数据口径;防作假边界沿用 ADR 0006/0007 与 spec 0004 既有口径)
**Tickets:** 78(矩阵榜单)/ 79(EvalCard 矩阵化 + 堆叠条退役 + 规范登记);本 spec 取代 spec 0007 的堆叠条形态(ticket 75/77 交付物)

## 背景

用户实机反馈现行堆叠条榜单(spec 0007 / ticket 75+77):「总觉得不好看,也不方便展示,也没有对齐」。grill 后确认两个阅读场景**都要**:3 秒看出谁最强(总分排名),同时一眼看出每个模型哪项强、哪项弱(逐维度)。现行结构在这两个场景上都有结构性缺陷:

1. **对齐是结构性不可能的。** ① 行是 flex 布局,family tag 宽度不一(`kimi` vs `claude`),每条 bar 左边缘随行漂移;② SuiteRuler 拿第一行分数算段位置,而段宽 = 分数 × 权重**每行不同**——ruler 只对第一行准确,对其余行全部错位。只要段宽随分数变,固定标尺就对不齐,这是 ticket 77 设计的内在矛盾,不是样式 bug。
2. **强弱不可见。** 五色分类色(ticket 77,--hs-suite-1..6)只表达「这是哪个维度」,不表达「分数好不好」——紫 100 与紫 60 同色;「弱」只能靠段宽间接猜,而段宽跨行不对齐,猜都猜不准。
3. **语义撞车。** 分类色借了功能色:suite-3 = danger 红、suite-4 = warning 橙、suite-5 = success 绿(semantics.css)。满分「代码 100.0」显示红色、「知识问答 100.0」显示橙色,读者直觉读作「危险/警告」。
4. **信息三处重复。** 能力点名字同时出现在:工具条维度切换 radio、SuiteLegend 图例行、SuiteRuler 标尺行。

## 决策总览(2026-07-27 grill 共识,逐项确认)

| 域 | 决策 |
|---|---|
| 布局 | **矩阵列式**:`名次 │ 模型(+family tag) │ 总分 │ 涨跌 │ 各维度列`,每维度固定一列,全列上下严格对齐 |
| 维度格子 | **数字 + 细条**:档色数字(600)+ 4px 档色细条;**条刻度恒 0–100**(绝对分制的视觉镜像,跨行跨批次可比) |
| 强弱色 | 档色口径不变(≥80 绿 / ≥50 黄 / <50 红);档色同时承担强弱表达,**五色分类色整体退役** |
| 总分列 | xl(20px)墨色大数字(**不染档色**)+ 6px 档色条(比维度 4px 粗一档);层级靠字号与条粗 |
| 排序交互 | **点列头排序**(带 ↓ 指示;再点 = 回总分降序——后端 `sortReportRows` 恒降序无方向参数,升序另票加 `order` 参数,2026-07-27 阶段 1 裁决);废维度切换 radio 与排序 select;工具条只剩 family 筛选 + 涨跌基准说明 + 分享图片;**涨跌列常显**(总分列常显,不再误导) |
| live 模式 | 未判分格子显 `–` + tooltip;总分墨色数字 + 空轨道**不染档色**(半成品构造上读不成「差」);rank dash、禁排序、隐涨跌;「N 个维度进行中 · N 个失败」灰注保留 |
| EvalCard | **物料同步换静态矩阵**(外框约定、20 行封顶、水印规则不变);ScoreStackBar/SuiteLegend/SuiteRuler 删除;新抽 **ScoreBar 单元组件**(数字+细条,页面/静态双模式)双端复用;`--hs-suite-*` token 退役 |
| 名次强调 | 前 3 名名次数字 brand teal + 600 字重,其余中性灰 |

## 矩阵榜单(页面)

### 行与列构成

- 列序固定:`名次 │ 模型 │ 总分 │ 涨跌 │ {suite 1..N}`;模型列 = 模型名(截断 + `title` 全显)+ family tag(el-tag plain,现状保留);维度列 = `report.suites` 固定顺序,flex 等宽(与 EvalProgressGrid 能力点列同例),**列宽与权重无关**——权重只影响总分(后端口径,不动)。
- 全表 CSS grid 或等价定宽列:名次/模型/总分/涨跌列定宽,维度列等分剩余宽;**每列 x 位置全表恒定**,上下严格对齐(取代 flex + 变宽 tag 的漂移)。
- 行点击/键盘下钻 ModelTrendDialog、hover 反馈、空态/失败态文案、settle 转场轮询与 ElMessage 全部不变。

### 维度格子(ScoreBar 单元组件)

- 新共享组件(暂名 `ScoreCell.vue`,开票定名):`{ score, cell, staticMode? }` 接缝,页面(Leaderboard)与物料(EvalCard)双端复用——共享接缝从「堆叠条」换成「格子」,双端一致性守住。
- 构成:`formatScore` 数字(`--hs-text-md`/600,**档色着色**)+ 其下 4px 细条(档色填充,`--hs-brand-soft` 轨道,`--hs-radius-xs`)。
- **条刻度恒 0–100**:87.5 的条永远比 100 短一截;不做行内/列内归一化(W7 绝对分制的视觉镜像)。
- 档色映射:≥80 `--hs-success` / ≥50 `--hs-warning` / <50 `--hs-danger`(阈值口径不动);null(未判分)→ `–` 占位(`--hs-text-placeholder`)+ 空轨道。
- **覆盖率水印(防作假硬约束,沿用)**:done 且 `judged < expected` 的格子,分数后随 `·8/10` 压缩水印(同色弱化);宽度不够省略,**tooltip 恒兜底**「能力点名 · 分数 · 判分 X/Y 题 · 采样 N 次」(ticket 51 confidence 口径);静态物料按页面同规则渲染,tooltip 不进物料(已登记的已知信息差)。

### 总分列与涨跌列

- 总分:`--hs-text-xl`(20px)/600,`--hs-text-primary` **墨色不染档色**;其下 6px 条(档色填充,0–100 同刻度)。层级靠字号 + 条粗(6px vs 4px),不靠颜色。
- 涨跌:**常显**(settled 批次)——总分列常显,涨跌贴着总分永不误导;spec 0007「维度视图隐藏涨跌」条款作废(堆叠条时代遗物)。行级口径不变:delta 非零显 ▲▼ + `formatScoreDelta`(升绿降红),null/持平/不可比显 `–` 占位;不可比三分支文案(题目已变更/判分口径已变更/考核口径不同)不变。
- 名次:settled 显数字,**前 3 名 `--hs-brand` + 600 字重**,其余 `--hs-text-secondary`;live 一律 `–` 占位(现有口径)。

### 工具条与排序

- 工具条收敛为:`family 筛选(select,现状)` + 右端 `涨跌基准说明(baselineNote)` + `分享图片/保存图片按钮`。废掉:维度切换 radio(矩阵下所有维度分同屏常显,「聚焦 + 变灰」无意义)、排序 select(列头即排序)。
- **点列头排序**:点「总分」或任一维度列头 = 按该列降序,列头带 ↓ 指示;再点当前列 = 回总分降序(排序归位);排序走现有 `query.sort` 服务端语义(不改 API)。**升序不在本 spec 范围**:后端 `sortReportRows` 恒降序、无方向参数(2026-07-27 阶段 1 裁决,升序需求另开后端小票加 `order` 参数);禁止前端本地 reverse(第二排序口径,防作假自洽性受损)。当前排序列头带指示,其余列头 hover 反馈可点。
- live 模式:排序禁用(列头不可点),行序保持后端字典序,「进度网格 / 实时分数」切换保留在工具条首位(现有)。

### live 模式(运行中/等待中批次)

- 已判分维度格子照常(数字 + 细条 + 档色 + 水印);未判分格子显 `–`(`--hs-text-placeholder`)+ 空轨道,tooltip 说明「进行中/等待中」。
- 总分列:**墨色数字 + 空轨道,不染档色、不填充**——半成品总分(如只判完 2/5 维度的 40 分)构造上不可能被档色读作「差」(spec 0004 半成品边界在视觉层的镜像)。
- 行尾(末列之后)灰字注:`N 个维度进行中` + 有失败追加 `· N 个失败`(danger 色),口径沿用 ticket 75。
- rank `–`、禁排序、隐涨跌列(整列不渲染,不占位);其余 live 约束不变。

## EvalCard 分享卡(物料)

- **构成同步换矩阵**:卡片 = 品牌区 + 范围行 chips + failed 警示行 + **矩阵行(静态版)** + 页脚;外框约定(720px、2x、恒亮主题、离屏双份捕获、复制降级、20 行封顶与收尾行、空筛选中性态)全部沿用 spec 0007 / ui-guidelines ticket 76 条目,一字不改。
- 矩阵行与页面同构(名次 + 模型 + 总分 + 涨跌 + 维度格子),`staticMode` 渲染:无 hover/tooltip,水印按页面同规则;涨跌列渲染条件 = 基准可比(总分列常显,故条件简化为可比性判断)。
- 范围行 chips 修订:删「维度」chip(无非总分视图了)、删「排序 ≠ 维度键」特判;保留:批次(恒列)/ 系列(有筛选)/ 排序(非默认)/ 涨跌基准(总分视图→恒列,缺失不渲染)。chip 顺序:批次 → 系列 → 排序 → 涨跌基准。
- 导出文件名、入口三处、文案(分享图片/保存图片/复制链接)不变。

## 删除与退役

- 删组件:`ScoreStackBar.vue`、`SuiteLegend.vue`、`SuiteRuler.vue`;删 `utils/stackSegments.ts` 主体(`liveCounts` 等仍被引用的纯函数迁入新 util)。
- 退役 token:`--hs-suite-1..6`(semantics.css 亮暗两块)——分类色方案整体退出;semantics.css 相应条目删除。
- 能力点名字从三处(radio/图例/标尺)收敛为一处:**列头**。

## 对既有规范的修订(ui-guidelines.md,plan agent 登记)

- §5「ScoreStackBar 是榜单堆叠条的唯一共享组件」条目**整体改写为矩阵条目**(本 spec 为准),ticket 75 段宽口径/高亮联动等约定标注 superseded;「Leaderboard 运行中半成品模式」(ticket 52)按本 spec live 节修订;ticket 77(五色分类色 + SuiteLegend/SuiteRuler)整条废止并登记废止理由(对齐结构性不可能 + 强弱不可见 + 功能色撞车)。
- §5 EvalCard 条目:堆叠条构成改为矩阵构成,范围 chips 修订如上;其余条款(外框/封顶/静态规则)不动。
- §3 语义色映射不变(档色阈值沿用);新增登记:榜单档色同时承担维度格子与总分条的强弱表达;`--hs-suite-*` 从语义令牌表删除。
- spec 0007 相应章节标注「已被 spec 0009 supersede」。
- 不改后端:rows / suite_scores / cells / weights / baseline 数据齐备,纯前端改造,W1–W8 无触碰。

## Testing Decisions

纯前端票,不新增 W1 接缝(HTTP 黑盒)测试;核心逻辑抽纯函数走 vitest(参照 `utils/statusCardSummary.test.ts` 先例):

- **格子与档色**:`scoreTier(score)` 档色映射(80/50 边界、null)、`formatScore` 沿用;live 计数(`liveCounts` 迁移后)单测保持绿。
- **快照**:`buildEvalCardSnapshot` 修订单测——chips 新集合(无维度 chip/排序 chip 特判删除/基准恒列)、矩阵行构造、20 行封顶与收尾计数、空筛选中性态。
- **排序**:列头排序状态机(降→升→列切换)纯函数单测;服务端 `query.sort` 参数拼装不变(现有测试保持绿)。
- **手测清单**:全表列对齐(不同 family tag 宽度下);live 半成品总分无档色;暗色抽查(档色两主题同值、占位灰可读);HTTP 裸 IP 复制降级;暗色会话导出亮主题 PNG;长模型名截断;前 3 名 brand 色。
