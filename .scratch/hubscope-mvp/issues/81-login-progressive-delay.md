## 风险登记

1. **延迟挂起的 goroutine 界**:分布式喷溅下数千个睡眠 goroutine 为已登记接受界(spec 决策 3);实现用 `time.Sleep` 或 timer 均可,注意请求中途客户端断开不应 panic
2. **W4 边界**:登录延迟是请求路径行为,非周期作业,不经调度器时钟;测试加速走 option 注入延迟表,不假时钟
3. **并发正确性**:同一用户名并发失败时计数与延迟档判定要经 mutex(与 ipLimiter 同纪律),竞态下延迟档可以「偏高一档」但不能丢计数方向相反
4. **单连接 SQLite(W2)无关**:本票不碰 store,延迟期间不得持有任何 DB 资源

## 备注(阶段 1 影响分析裁决登记,2026-07-27)

- **阈值语义采 spec 口径**:失败满 5 次后自第 6 次起延迟(ticket 验收清单初稿「第 5 次起」为笔误,已修;spec 语义下存量 `TestRateLimitEntryCap` 恰好 5 次失败零减速)。
- **三个失败分支统一计数**:用户不存在 / 账户禁用 / 密码错误走单一失败出口,统一计数、统一延迟档——不给分支间制造可分辨的行为差异;禁用账户持正确密码也会延迟,但本就登不进,无合法用户伤害。
- **已知残留(本票不修)**:阈值之下「用户不存在 vs 密码错误」存在既有 bcrypt 时序差(~50-100ms),是既有枚举旁路;阈值之上被退避延迟掩盖。登记备查,非本票验收项。
- **per-entry 时间戳切片必须封顶**(plan 发现):保留 threshold + len(backoff) 个即可,否则分布式攻击打同一用户名时窗口内时间戳无限堆积,单 key 维度绕过 map 硬上限。
- **ctx-aware sleep**:延迟经 `select` on 请求 Context 实现,客户端断开提前释放 goroutine;不持锁睡眠(递增/算档在锁内,出锁再睡)。
